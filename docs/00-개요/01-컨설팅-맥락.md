# 01. 컨설팅 맥락 (인계용)

> 2026-11-25 기준. 다른 AI 도구(예: Aside)에서 이 컨설팅을 이어서 진행하기 위해 전체 맥락을 한 문서로 정리함.
> 상세 내용은 각 안건 문서 참고. 저장소: https://github.com/JayAhn0104/ax-consulting-kyuryul

## 1. 이 문서를 읽는 AI에게

- 역할: 컨설턴트(안재형)의 작업 파트너. 클라이언트의 업무 문제를 정의하고, AI로 해결하는 도구를 기획·구현함
- 진행 원칙
  - **문제 정의 → 해결 방향 가설 → 시험 → 구현** 순서. 구현부터 하지 않음
  - AI가 거의 모든 작성을 맡고, 사람은 원자료 입력·설정·검토·승인만 담당하는 형태를 지향
  - 결제, 등록·공개, 고객에게 보내는 메시지처럼 책임이 따르는 동작은 항상 사람 승인 후 실행
- 문서 작성 방식
  - 한국어, 개조식, 객관적 서술. 이모지 사용 안 함
  - 클라이언트는 "클라이언트"로 지칭. 미확인 내용은 "(확인 필요)"로 표기
  - 플랫폼 용어는 네이버·쿠팡 공식 명칭을 그대로 사용 (임의 분류·명칭 만들지 않음)
  - 클라이언트용 화면은 네이버 판매자센터처럼 익숙한 플랫폼 스타일로 구성 (일반적인 AI 서비스 느낌 지양)
- 보안
  - API 키, 계정 정보, 판매자센터 화면 캡처는 문서·저장소에 넣지 않음
  - 클라이언트 고객의 개인정보는 다루지 않거나 최소한으로 다룸

## 2. 클라이언트와 컨설팅

- **클라이언트**: 강규렬. 온라인 커머스 1인 운영 (운영 인원 확인 필요)
- **컨설턴트**: 안재형 (AI Agent 개발자). 지인 대상 무료 AX 컨설팅. 이 건이 첫 사례
- **클라이언트 환경**: Windows PC. ChatGPT 요금제 사용 (Plus / Pro 확인 필요). 비개발자
- **진행 단계**: 안건 1은 시제품 완료 후 웹서비스 전환 기획 중. 안건 2·4는 문제 정의 완료. 안건 3은 미정의

## 3. 사업 현황

### A. 식물 판매 — 꿈을 심는 정원 (재고형)

- 국내 도매로 실내 식물을 매입 → 자체 창고 보관 → 직접 촬영·등록 → 직접 포장·발송
- 판매 채널: 네이버 스마트스토어(운영 중), 쿠팡(신규 예정)
- 다품종이라 **신규 상품 등록 속도**가 경쟁력. 등록 작업이 주요 병목

### B. 해외구매대행 (무재고형)

- 타오바오 상품을 스마트스토어 25개에 등록하고, 주문이 들어오면 매입
- 네이버 스토어당 상품 수 제한, 사업자당 스토어 3개 제한 때문에 사업자 10개 보유
- 사용 도구: 부스터로더(상품 선별·업로드, 강의 제공 도구), shopmine(다중 스토어 주문 수집), 중국 배송대행지
- 주문 흐름

```
shopmine 주문 수집 → 타오바오에서 같은 상품 검색 → 진행 검토(무게·제한 품목·현재가)
→ 타오바오 주문·결제 → 판매자 채팅 문의(중국어) → 배송대행지 신청
→ 입고 사진 검수 → 포장 옵션·결제 → 국내 발송 → 스마트스토어 송장 입력
```

## 5. 안건 1 — 식물 상품 등록 자동화

### 목표

```
입력:  직접 촬영한 사진 + 식물 이름·구성·매입가
출력:  네이버(1차)·쿠팡(다음 단계) 등록 항목 값, 상세페이지 이미지
등록:  검토 후 네이버 커머스API로 비공개 등록 → 확인 후 판매 공개
```

### 완료된 것 — Codex PoC (plant-agent 작업공간)

- ChatGPT 앱의 Codex에 `plant-agent` 폴더를 프로젝트로 연결하고, 채팅으로 사진·정보를 주면 AI가 작업
- 구성
  - `AGENTS.md`: 에이전트 지침 (단일 원본)
  - `작성기준.md`: 섹션별 작성 기준. 클라이언트가 말로 요청하면 AI가 기준을 수정. `render_criteria.py`가 HTML 페이지로 표시
  - `products/<날짜_상품명>/product.json`: 상품 데이터의 단일 원본
  - `scripts/`: price(가격 계산), prepare_images(대표이미지·순서), validate(금지어·규칙 검사), render_preview(판매자센터 순서의 검토 화면), export_detail(상세 HTML → 780px 이미지), naver_api(커머스API 등록·조회), shopping_insight(쇼핑인사이트 수요 조회), category_history
  - `config/`: 스토어 기본 설정, 상품명·태그 규칙, 비밀 키(별도 파일, 저장소 제외)
- 시연(2026-10-30, 송오브인디아): 작성 → 미리보기 검토 → 작성 기준 페이지 → 네이버 비공개 등록까지 성공
- 클라이언트 전달용 사용 흐름 문서·영상 제작 완료

### 진행 중 — 로컬 웹서비스 전환 (기획·설계 완료, 개발 전)

- 이유: 채팅 방식은 무엇을 요청해야 할지 매번 판단해야 하고, 등록·공개도 말로 요청하며, 상품별 진행 상태가 보이지 않음
- 결정 사항
  - 클라이언트 PC에서 실행하는 로컬 웹서비스 (FastAPI, 127.0.0.1). 네이버 커머스API IP 제한을 PC IP로 충족
  - AI 엔진: Codex app-server(ChatGPT 앱 내장). "ChatGPT로 로그인"으로 클라이언트 요금제 사용, API 비용 없음. AI 연결부는 한 모듈로 분리해 엔진 교체 가능
  - 화면: 단계형 ① 정보 입력 → ② 작성·검토 → ③ 네이버 등록 → ④ 판매 공개. 채팅창 없이 섹션별 수정 요청 칸
  - 상세페이지 요청은 정보 입력 단계에 포함
  - 등록·공개는 화면 버튼이 스크립트를 직접 실행 (AI는 실행하지 않음)
  - 데이터는 작업공간 파일 (별도 DB 없음)
  - 1차 네이버, 쿠팡은 다음 단계. Vercel 등 호스팅 사용 안 함. 모바일은 추후 Tailscale·Cloudflare Tunnel
- 기술 검증(2026-11-24): app-server 로그인, 사진으로 상품명 작성(16초), 대표이미지 배경 보정(58초) 성공. AI 질문 도구는 일반 모드에서 동작하지 않아 자체 방식으로 대체
- 미결: AI 도구를 MCP(stdio) 서버로 제공하는 방식 검토, 샌드박스 네트워크 차단 여부, Windows에서 Codex 실행 경로
- 알려진 문제: 작성기준.md의 "변경 요청 예시"를 AI가 기준으로 오해함 → 예시 표기 수정 필요

### 새로 검토 중인 방향

- **브라우저 AI 에이전트(Aside 등)** 활용: API 대신 클라이언트가 로그인한 브라우저에서 AI가 판매자센터에 직접 등록. 커머스API 신청·IP 제한 없이 네이버·쿠팡에 같은 방식으로 등록 가능할 수 있음. 웹서비스 방식과 비교 필요

## 6. 안건 2 — 해외구매대행 주문 처리

- **문제**: 등록은 부스터로더로 원활. 부담은 주문 이후 단계에 집중. 스토어 25개 주문을 같은 수작업으로 처리하여 주문 수에 비례해 시간 증가
- **판단 지점**: 같은 상품인지, 진행할지(무게·위험물·통관 제한·현재가·마진), 결제, 판매자 답변 해석, 입고 검수
- **목표 형태**: AI가 같은 상품 찾기 → 검토표 작성 → 주문 준비 → 판매자 문의 작성·번역 → 배송대행지 신청서 입력. 클라이언트는 진행 결정과 결제 승인만
- **해결 방향 가설**
  - 타오바오 구매 기능·배송대행지는 쓸 만한 API가 거의 없으므로 **브라우저 AI 에이전트** 적합 (Aside, OpenClaw 등 조사 중)
  - 사람 승인 지점 고정: 진행 결정, 결제, 판매자에게 메시지 발송 전
  - 지시·승인은 메신저(텔레그램 또는 Slack) 검토
  - 1차는 상품 찾기·검토표만 자동화하여 정확도 확인
- **위험**: 결제 오류, 자동화 감지·계정 제한, 동일 상품 오판, 도구 성숙도, Windows 지원 여부
- **확인 필요**: 하루 주문 건수, 단계별 소요 시간, 진행 검토 기준, 배송대행지 업체·신청 방식, shopmine·부스터로더 기능 범위, 타오바오 계정·결제 방식

## 7. 안건 4 — 고객 CS

- **문제**: ① 문의가 스마트스토어 문의(25개 스토어), 톡톡, 쿠팡, 전화 등으로 분산 ② 작업·이동 중 불시 전화
- **목표 형태**
  - 문의 통합: 채널별 API로 수집 → 메신저(텔레그램 또는 Slack)로 일원화 → AI가 주문 정보 첨부·답변 초안 → 클라이언트 승인 → 해당 채널에 답변 등록
  - 전화 응대: 기존 번호 착신전환 → AI가 수신 → 주문 조회·배송/반품/관리법 안내 → 통화 요약을 메신저로 전달
- **전화 방안**: A 휴대폰 내장 기능 / B 전화 AI 플랫폼(예: CallBridge, 월 약 6~8만 원 예상, 14일 무료 체험) + 자체 응대 로직 / C 직접 구축(SIP + 실시간 음성 AI). 1차 검토안은 B안 체험. 피클(Pickle)은 발신 전용이라 제외
- **원칙**: 기존 고객센터 대행 서비스는 쓰지 않음. 범용 에이전트는 프롬프트 인젝션 위험으로 고객 문의 처리에 쓰지 않고, 권한을 좁힌 전용 흐름으로 구성
- **실행 환경**: 항상 켜진 클라우드 서버 + 고정 IP. AI 비용은 API 과금
- **확인 필요**: 채널별 문의 건수·유형, 전화 건수·통화 시간, 고객센터 번호 형태, 휴대폰 기종, 선호 메신저, 기존 응대 문구
